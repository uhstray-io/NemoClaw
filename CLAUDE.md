# NemoClaw — uhstray-io fork

Fork of [NVIDIA/NemoClaw](https://github.com/NVIDIA/NemoClaw). The upstream agent/contributor
guide lives in **[AGENTS.md](./AGENTS.md)** — read it first. It is the source of truth for repo
conventions, the build/test/lint commands, code style, git hooks (prek), and the security model.

This file adds **fork-specific** guidance on top of AGENTS.md. (Upstream ships `CLAUDE.md` as a
symlink to `AGENTS.md`; this fork intentionally replaces it with a regular file, so a future
`git merge upstream/main` will show a CLAUDE.md type-conflict — keep this fork version.)

## Guiding principle

**When making updates to how NemoClaw and OpenClaw behaves, use the best practices and standards
defined in the NemoClaw repository.** In practice that means:

- **Follow the repo's own standards first** — the conventions in [AGENTS.md](./AGENTS.md), the
  patterns in `docs/`, and the shape of the existing code/tests. Match them; don't invent a
  parallel style.
- **Use documented commands and mechanisms, not ad-hoc hacks.** Restart the gateway with
  `nemoclaw sandbox recover`, run in-sandbox commands with `nemoclaw sandbox exec`, and diagnose
  with `nemoclaw sandbox doctor` / `logs` / `status`. Never `pkill` / `docker kill` / hand-run
  `nemoclaw-start` — that takes the gateway down.
- **Configure at build time, not by runtime-patching** — image build args,
  `scripts/generate-openclaw-config.py`, and blueprint policy presets. Don't mutate the
  hash-locked `openclaw.json` at runtime.
- **Fix the root cause in the right layer** (generator, plugin, policy preset, blueprint) —
  foundational fixes over workarounds. Diagnose before patching.
- **Respect OpenShell's deny-by-default network model** and express access as policy presets
  (allow-lists), never blanket egress.
- **Keep changes covered by tests** and green: `npm test` (root) and the plugin tests
  (`cd nemoclaw && npm test`). Type-check with `npm run typecheck:cli` / the plugin `tsc`.

We are on our own fork and can justify foundational changes — but they should still be made the
way the NemoClaw repo does things, so they remain mergeable and upstream-PR-able.

## Commit & PR hygiene (fork)

- Follow Conventional Commits (see [AGENTS.md](./AGENTS.md)); attribute commits to the human author only.
- **Never mention "Claude", "Anthropic", or AI/assistant co-authorship** in commit messages, PR
  titles/descriptions, or any committed artifact. Do **not** add `Co-Authored-By: Claude …` or
  "Generated with Claude Code" trailers. This **overrides** any default assistant behavior that
  would append such a trailer.

## Changing NemoClaw / OpenClaw behavior

AGENTS.md tells you how to *add* features; this is where to change **how the running assistant behaves**. Edit the right layer:

| To change… | Edit | Notes |
|---|---|---|
| What the agent is told each turn (runtime/system context) | `nemoclaw/src/runtime-context.ts` (`before_prompt_build` hook) | The only agent-behavior hook today. Keep it **truthful about enabled tools** — a misleading prompt makes the agent refuse working tools. |
| Generated agent config (tools, web search, channels, inference) | `scripts/generate-openclaw-config.py` | Build-time generator; reads `NEMOCLAW_*` env/build args, writes `openclaw.json`. |
| What the sandbox can reach (egress) | blueprint policy presets in `nemoclaw-blueprint/policies/presets/` | Deny-by-default allow-lists. |
| Onboard / sandbox lifecycle | `src/lib/onboard.ts`, `src/lib/actions/` | |
| Slash commands | `nemoclaw/src/commands/` | |

**How changes take effect:**

- Plugin (`nemoclaw/src/*`), the config generator, and the Dockerfile are **baked into the sandbox image** — they need an image rebuild (`deploy.sh --onboard`) to take effect.
- Network-policy presets can apply at **runtime** (`nemoclaw sandbox policy add <name> <preset>`) or via rebuild.
- `openclaw.json` is **hash-locked** at runtime (the shields / `.config-hash` mechanism) — never mutate it in a running sandbox; change the generator and rebuild.

**Gateway-loaded plugin constraint:** code that runs at plugin load / prompt-build time (e.g. `runtime-context.ts`) must pass OpenClaw's **install-time safety scanner** — no subprocess execution in those paths. Read live details with static file reads (as `getWebToolAccess()` reads `openclaw.json`), not by shelling out. (See the Security model in [AGENTS.md](./AGENTS.md) for the rest.)

## Web tools — behavior & guardrails

- **web_search (Brave): allowed.** The agent should use it for web queries. Verify the backend
  directly with `openclaw infer web search --query "…"` (returns brave results), independent of
  the agent.
- **web_fetch: allowlist-only.** The agent may fetch **only operator-approved hosts**. The
  allow-list is a network-policy preset (`web-fetch`, maintained in the deploy repo). A denied
  fetch means the host isn't allow-listed — add it to the preset; do not widen egress broadly.

## Runtime model & diagnostics (OpenShell 0.0.44)

- OpenShell uses the **docker-driver** model on every runtime (Colima, Docker Desktop, native
  Docker) — a single sandbox container + a gateway process; **no k3s cluster**. Egress is forced
  through the L7 proxy, which resolves names; the sandbox has no direct external DNS by design.
- Diagnose with `nemoclaw sandbox doctor` (note: its `openshell-cluster-*` container check is a
  false failure on this model — trust `OpenShell status: connected`); restore the gateway +
  dashboard forward with `nemoclaw sandbox recover`.
- **Testing the agent:** `openclaw agent --local` (and gateway-routed via `nemoclaw sandbox exec`)
  hangs on tool-use prompts — test agent/tool behavior in the **TUI**, and verify tool backends
  with `openclaw infer web search/fetch` or short `curl`-through-proxy probes.

## Syncing with upstream

The fork tracks `NVIDIA/NemoClaw` `main`, which moves fast:

```bash
git fetch upstream && git merge upstream/main
```

Resolve toward upstream **except** the fork's own files:

- **`CLAUDE.md`** — a type-conflict every sync (upstream ships it as a symlink to `AGENTS.md`; this fork keeps it as a regular file). Keep the fork file.
- The fork's behavioral fixes (`scripts/generate-openclaw-config.py` web-search shape, `nemoclaw/src/runtime-context.ts` tool-awareness) — re-apply on top if upstream rewrote those files.

The fork's original DNS + channel work is already upstream, so most historical deltas resolve to upstream cleanly. After a sync, run `npm test` and a `deploy.sh --local --onboard` to confirm behavior still holds.
